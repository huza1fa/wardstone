# Operator reliability batch — October 19, 2026

This batch adds configured file evidence, operator case controls, an opt-in
synthetic approved-execution pilot, and a saved-case evaluation CLI. Existing
Jira/Google credentials and routing policy remain usable. Production
infrastructure mutations remain denied in SHADOW and REVIEW.

## Upgrade an existing installation

The runtime now requires schema versions **1 through 12**. Migrations are applied
by the administrator, not automatically at startup. Stop the previous process,
back up PostgreSQL to a location outside the repository, and apply missing
migrations in numeric order. For an installation already at schema 10:

```sh
pg_dump "$WARDSTONE_DATABASE_URL" --format=custom \
  --file=/path/outside/repo/wardstone-before-upgrade.dump
psql "$WARDSTONE_DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f migrations/000011_operator_cases.sql \
  -f migrations/000012_test_execution.sql
```

Migration 11 backfills each existing investigation as its own case root, preserving
investigation IDs and historical evidence/drafts. Migration 12 adds execution
leases/phases and separate synthetic connector state. Existing execution rows
without the new pilot approval binding are preserved. Startup fails on an
incomplete/outdated migration history. Switching to an older binary requires
restoring its matching database backup; no automatic downgrade is provided.

Build all three binaries, start Wardstone with the existing environment, and use
Setup to inspect readiness. Console intake requires the model worker; synthetic
execution is separately disabled until `WARDSTONE_TEST_EXECUTION_ENABLED=true`.
The [operator guide](operator-guide.md) explains the controls, failure states,
recovery behavior, and evaluation commands.

Configured PDF extraction additionally needs Linux, Poppler, Bubblewrap,
`prlimit`, and working unprivileged namespace isolation. Missing prerequisites
produce evidence gaps; public text sources continue to work. See
[file evidence setup](development.md#vendor-sources-and-systems-runbooks).

## Running while the primary administrator is away

Keep the existing single-administrator trust model explicit to anyone sharing the
installation. Operator names are audit attribution under the shared bearer token.
Give friends the operator guide and access to the service logs and PostgreSQL
backup process. Failed/uncertain work remains visible and bounded rather than
being replayed indefinitely. Model/backend errors can be addressed by cancelling
or retrying an attempt; Jira uncertainty still requires the existing explicit
comment verification/resend decision. Do not reset delivery state in SQL to force
an uncertain send to repeat.

The synthetic pilot can stay disabled for regular use. Evaluation tooling defaults
to offline fixtures and never runs on a schedule. Both need an explicit operator
choice to exercise their optional behavior. Real Google execution, OCR, multi-user
permissions, and evaluation of interactive trajectories remain future work.

## Validation

Use the complete local verification command with a disposable migrated PostgreSQL:

```sh
WARDSTONE_TEST_DATABASE_URL=postgres://... scripts/verify.sh
```

The script requires a test database so integration coverage cannot silently skip.
CI runs migrations, vet, race tests, the browser-script tests, all binary builds,
and the offline evaluation baseline. The test execution recovery scenarios use
real PostgreSQL connector state and recreate in-process components after crashes.
The model comparison protocol tests use a local fixture server; no paid provider
or real infrastructure is required by the verification suite.
